# 企业微信表格超过 200 行的读取方案

状态：已接入本地工作台“完整读取并预览”，完成模拟分页、三张真实表的双遍读取测试及本地桌面浏览器基本展示与交互验收。真实手机和企业微信内置浏览器、dev 环境联调仍待验收。普通“预览网页”保留最多 200 行的快速预览，禁止发布；只有完整读取、两次内容核对通过的数据才能发布。本功能不涉及发布授权。

## 读取与发布分开

- 样例读取：最多 10 行，用于验证字段映射。
- 快速预览：最多 200 行，明确显示“部分数据，不可发布”。即使不足 200 行，也不能仅凭数量判断完整。
- 完整读取：每批最多 200 行，连续分页至结束；生成一份独立的完整预览。用户确认这份预览后，才能提交该份数据。
- 页面展示读取已发布的数据快照，不让每台教室设备分别调用企业微信、遍历表格。

## 分页协议

1. 开始时检查 CLI 版本、授权、用户选择的表格和子表、所有映射字段。缺少任一字段就报错，不静默丢弃。读取并保留源记录总数（缺失不是 0）。冻结本次映射配置及其摘要。
2. 只请求当前模块所需字段。每批数量取 `min(200, floor(9999 / 字段数))`，满足单次返回单元格数量小于 10000 的要求。
3. 首次请求不传 cursor；后续使用上一响应实际返回的 next_cursor。不得自行推算行号或构造游标。
4. 按服务端分页结束信号判断完成，不以“本批不足 200 行”代替结束条件。上线前用真实 CLI 响应确认终止字段契约；信号缺失、含义不明确或互相矛盾时按未完成处理。
5. 例如 450 行，以 200、200、50 三批读取；恰好 400 行也必须确认末页终止信号，必要时继续请求，不能仅因凑满两批而停止。
6. 内部记录标识用于检查重复，不传到公开展示数据。重复记录、循环游标、空页却要求继续、返回格式错误均中止本次任务，不静默去重后宣称完整。

## 本地任务与进度

采用任务式读取，不在一次 HTTP 请求中循环读完整张表：

- 开始：创建随机本地任务编号，绑定登录会话、模块、映射摘要和读取参数。
- 继续：每次只推进一批；浏览器显示“已读取 400 / 450 行，第 2 批”。源总数未知时只显示已读取数量。
- 状态：pending → reading → verifying → ready；其他终态为 failed、cancelled、expired。
- 同一任务禁止并发推进；使用批次序号防止重复点击、响应丢失后的重复追加。网络结果不明确时先查任务状态。
- 游标和原始记录仅保存在本机服务端，不放入 URL、浏览器存储或日志；响应只包含进度和必要的预览信息。
- 单次 CLI 调用超时 30 秒；任务闲置 15 分钟过期。每遍读取最多 10000 源记录、20 MB 累积数据、100 批；同时最多保留 30 个任务，触及上限明确失败，不截断为成功。上限是资源保护，不是默认读取目标。
- 提供取消按钮；取消后的在途返回不得继续入库，也不得替换已准备好的快照。

## 完整性与一致性

- 完整标记由服务端产生，前端不能自行指定。发布必须检查终止信号、累计行数、映射摘要、解析问题、内容大小及目标接口容量。
- 读取结束后重新检查子表记录总数：前后数量应一致，并与本次累计数量相等。总数缺失或对不上，不允许发布。
- 数量相同不代表内容未改变。分页接口没有已确认的快照一致性保证：发布准备阶段再次完整读取，按内部记录标识排序后比较所选字段内容摘要；两次不同则提示表格发生变化，重新准备。
- 双次校验仍不等同于数据库事务快照。读取期间应避免编辑源表；后续改动需重新读取，不自动混入已确认的发布包。
- 校历的“源记录数”和“解析后的事件数”分别展示。例如 300 行可能拆成 900 条事件，不能用事件数反推读取是否完整。
- 当前校历仍限制 500 条解析后的事件、值周 2000 条，待发布内容限制 900 KiB；完整读取完成时会提前校验，超过容量须说明原因，不取前若干条发布。本次没有扩大云端容量；扩容需另做性能验收。

## 中断处理

- CLI 超时、权限异常、解析错误等立即停止，不自动无限重试，也不发布已读部分。子表相关错误先重新确认子表是否存在，再给出权限或选择错误提示。
- 浏览器断开但本地任务仍有效：查询任务状态后继续请求下一批，不重复追加上一批。
- 服务重启、任务过期、游标失效、映射变化或源表变化：废弃该次读取，从头重新准备。首版不支持跨重启断点续传，避免用旧游标拼接新的表格内容。
- 只有 ready 状态才将完整解析结果一次性替换对应的本地待发布预览；失败不清空现有已发布页面。重读开始后，界面应禁止误发上一次的旧准备结果。

## 发布边界

全量读取成功 ≠ 已发布。流程为：完整读取 → 校验 → 本地完整预览 → 用户确认目标和数据 → dev 数据发布 → 验收 → 最终批准后 main。

代码推送与数据发布是两个操作；读取任务不推送代码、不合并分支、不写企业微信表格，也不修改生产 Blob。

## 必测用例

- 0、1、199、200、201、400、450 行，以及字段较多导致批量不足 200 的情况。
- 最后一批恰好满额、空末页、缺失终止信号、循环游标、重复记录、错误响应和畸形 records。
- 第二批超时、请求响应丢失、双击继续、取消、会话失效、任务过期和本地服务重启。
- 前后总数变化、总数不变但内容变化、字段删除/改名、读取过程中修改映射。
- 校历一行多事件、中文换行和成员字段；超过输出容量、空结果、有解析错误时禁止发布。
- 失败后旧线上页面不变；前端伪造 complete、任务编号或模块不能绕过服务端校验。

## 实施顺序

1. 为企业微信桥接层增加单页读取、超时、响应协议校验，用模拟响应做分页测试。
2. 添加本地任务管理和 start / next / status / cancel 接口，验证会话隔离、幂等与中断处理。
3. 工作台接入“完整读取并预览”和进度，发布端用完整性证据替换目前的 200 行拦截。
4. 在获准读取的真实表格上验证超过 200 行的末页契约和记录总数；先验收本地，再进行经批准的 dev 测试。

前三项已接入代码，第四项的真实读取部分已完成。CLI 1.2.0 的真实末页会省略 has_more 和 next_cursor；适配器仅在响应明确成功、响应 total 与源表总数相等、累计读取数恰好等于该总数时接受这种末页。其他缺失终止信息仍失败关闭；后续源表总数和双遍内容核对照常执行。完全空白记录可能省略 values，计入源行数但不生成展示内容。

刷新同一浏览器标签页后可按“继续读取”查询并恢复任务；浏览器只保存本地任务编号和模块名称，不保存企业微信分页信息。服务重启、任务过期或换登录会话后须取消旧任务再从头读取。
