# 校园工作台重构路线图

## 目标

项目采用“模块化单体”架构：一个 Vercel Web 应用承载公开页面、管理后台和 API，一个本地工作台负责企业微信授权、读取与同步。校历、作息和值班排班共享认证、映射、校验、版本和发布能力，不为每个功能复制一套后端。

核心数据流：

```text
企业微信智能表格
  → 本地工作台读取字段与记录
  → 字段映射（企业微信列 → 标准字段）
  → 数据校验与差异预览
  → Vercel API 接收草稿
  → 管理员发布版本
  → 网页按模块读取已发布数据
```

## 已落地的第一步

- `/admin/mappings/`：数据映射中心雏形。
- `config/module-mappings.seed.json`：校历、作息和值班排班的初始注册信息。
- `shared/module-mapping-model.cjs`：本地服务与 Vercel API 共用的映射校验。
- `/api/module-mappings`：管理员读取、保存和发布映射配置。
- 本地 Node 服务把映射保存到 `data/module-mappings.json`。
- Vercel 把映射保存到 Private Blob 的 `admin/module-mappings.json`。

这一阶段不改变现有公开页面的数据读取方式，避免在映射中心尚未接入真实企业微信字段前影响校历和作息。

## 映射模型

每个网页模块包含四部分：

1. `schema`：系统认可的标准字段，是网页和数据源之间的稳定契约。
2. `source`：企业微信文档、子表及本地工作台发现的字段。
3. `mappings`：企业微信字段到标准字段的转换规则。
4. `view`：网页展示方式、可见字段和排序规则。

企业微信登录态、Cookie、访问令牌等凭据不能进入映射模型，也不能上传到 Vercel。云端只保存文档标识、子表名称、字段元数据和映射规则。

## 分阶段实施

### 阶段一：稳定当前代码

- 为当前可运行版本建立 Git 基线。
- 拆分作息页面中的 HTML、CSS、展示逻辑、编辑逻辑和文件导入逻辑。
- 作息发布改用与校历相同的管理员令牌。
- 把本地 `server.js` 和 Vercel API 的校验逻辑移动到共享模块。
- 为校历、作息和映射模型增加自动化测试。

验收条件：现有三个稳定地址不变；本地和 Vercel 对相同输入给出相同校验结果。

### 阶段二：本地工作台

- [已完成] 建立仅监听 `127.0.0.1:3100` 的本地工作台页面。
- [已完成] 增加首次设置密码、加盐哈希存储、登录令牌和退出登录。
- [已完成] 显示企业微信 CLI 版本和授权状态。
- [已完成] 按用户填写的链接读取子表、字段和最多 8 行样例数据。
- [已完成] 将真实企业微信字段映射到网页标准字段并保存本地草稿。
- [待完成] 将 `scripts/sync-wecom-calendar.mjs` 的转换与发布能力并入通用连接器。
- [待完成] 本地工作台下载和上传 Vercel 映射配置。
- [待完成] 同步前展示新增、修改、删除和错误行。
- [待完成] 每台本地工作台使用独立设备凭据，替代按模块设置同步密钥。

验收条件：校历和作息使用同一条同步流程；企业微信凭据不会离开本机。

### 阶段三：数据库与版本发布

- 通过 Vercel Marketplace 接入 Postgres。
- 建立 `modules`、`data_sources`、`field_mappings`、`view_configs`、`sync_runs` 和 `content_versions`。
- Blob 仅保存原始表格、导入快照、附件和备份。
- 支持草稿、发布、历史版本和回滚。
- 每个内容版本记录生成它的映射版本。

验收条件：任何一次发布都能定位来源、操作者和映射版本，并能回滚到上一版本。

### 阶段四：值班排班与权限

- 实现 `/duty-roster/` 展示页面。
- 增加班次、人员、地点和调班规则。
- 接入企业微信身份，按角色控制模块编辑权。
- 增加排班变更通知和审计日志。

## 下一次开发建议

下一次优先完成“通用数据转换和同步草稿”。它会把本地预览结果发送到 Vercel 草稿区，并为后续的新增、修改、删除差异预览打基础。
